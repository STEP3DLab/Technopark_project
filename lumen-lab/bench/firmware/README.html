Прошивка USB-термометра LM04B

LM04B-Pico-v1.uf2 содержит загрузочный образ для классической Raspberry Pi Pico с RP2040 и флеш-памятью 2 МиБ. В образ входят официальная MicroPython RPI_PICO v1.25.0 и приложение main.py. Плата измеряет температуру двух внешних DS18B20 и передаёт результаты через USB CDC. Приложение не принимает управляющие команды.

Подключение датчиков

Цепь Контакт Pico Подключение
T1, DQ 4, GP2 DQ первого DS18B20, отдельный резистор 4,7 кОм к 3V3
T2, DQ 5, GP3 DQ второго DS18B20, отдельный резистор 4,7 кОм к 3V3
Питание 36, 3V3(OUT) VDD обоих датчиков
Общий провод 3 или 8, GND GND обоих датчиков

Каждый канал использует собственную трёхпроводную линию. Для готовых герметичных щупов назначение жил берут из документации поставщика. Распиновка Pico · Паспорт DS18B20, стр. 3–4 и 7–12

Загрузка готового образа

Полный образ заменит всё содержимое флеш-памяти Pico, включая существующие программы и файлы. Для обновления одного файла на плате с подходящей версией MicroPython предназначен отдельный способ ниже. При необходимости заранее скопируйте имеющиеся файлы с платы.

  1. Отсоедините Pico. Удерживая BOOTSEL, подключите кабель Micro-USB с передачей данных. Отпустите кнопку после появления съёмного тома RPI-RP2.
  2. Скопируйте LM04B-Pico-v1.uf2 на этот том. После загрузки том исчезнет и появится последовательный USB-порт.
  3. Выберите порт в программе стенда. Сначала удобно проверить строки с отключёнными датчиками, затем подключить каждый DS18B20 к своему разъёму. Исправный канал выдаёт ok и температуру, отключённый выдаёт no_sensor и null.

Для подтверждения записи всех блоков можно использовать picotool 2.1.1 с поддержкой USB. Подключите одну плату в режиме BOOTSEL и запустите команду из этой папки. Она загрузит образ, сравнит его с содержимым флеш-памяти и запустит плату. Загрузчик Pico · Руководство picotool

picotool load -v -x LM04B-Pico-v1.uf2

Размер образа — 4 194 304 байта. Полезные данные UF2 занимают 2 МиБ. SHA-256 файла — a8aa55f4dd7c13af16673c23b67dfabfadb04b277cf18639cd2f212dc96a4880.

Чтение с платы и обновление приложения

Команды выполняются на компьютере из этой папки в окружении Python 3.9 или новее. Для mpremote освободите порт, закрыв соединение в регистраторе или терминале. В командах укажите имя своей платы из списка портов. В Windows это может быть COM5, в Linux — /dev/ttyACM0, в macOS — /dev/cu.usbmodem…. Команды mpremote v1.25.0

python -m pip install mpremote==1.25.0
python -m mpremote connect list
python install.py --port COM5 --verify-only

Последняя команда проверяет тип платы и версию MicroPython, считывает с платы весь /main.py, побайтово сравнивает его с файлом комплекта и перезапускает приложение. SHA-256 исходника — e79e8607e32e1becf07f9c435a5c2b76b549a7e02f8791f69c0810f752bb6e2a.

Для обновления одного приложения на классической Pico с официальной RPI_PICO v1.25.0 используйте следующую команду. При необходимости сначала отдельно загрузите зафиксированную среду MicroPython через BOOTSEL. Исходный UF2 MicroPython

python install.py --port COM5

Установщик записывает временный файл, проверяет его SHA-256 на плате, заменяет /main.py операцией переименования, затем считывает итоговый файл и сравнивает байты. Другие пользовательские файлы сохраняются. Если на плате есть пользовательский boot.py, он должен передавать выполнение main.py. После неудачной передачи можно повторить установку. Ручной перезапуск после прерванного сеанса обслуживания выполняется командой python -m mpremote connect COM5 reset.

Для просмотра строк после запуска подойдёт python -m mpremote connect COM5 repl. Выход из просмотра — Ctrl+]. Обычная программа регистрации только читает данные. Плата продолжает измерения, когда окно регистрации закрыто.

Данные с платы

Примерно раз в секунду приложение начинает новый цикл на двух шинах. Оно проверяет единственность и CRC адреса каждого датчика, его семейство 28h и внешнее питание. После команды преобразования драйвер ожидает состояния «занят», затем «готов». При исправном ответе повторно проверяются адрес и CRC девяти байтов памяти результата. Оба преобразования идут одновременно. Предельное время ожидания для каждого — 850 мс. Команды и времена преобразования DS18B20

Каждая завершённая строка USB — один JSON-объект версии LM04B/1. При подключении посередине передачи читатель может получить хвост строки до первого перевода строки.

Поле Значение
board 8 байт аппаратного идентификатора платы, 16 строчных шестнадцатеричных цифр
boot 8 случайных байт нового сеанса, включая мягкий перезапуск приложения
seq Номер с нуля. Потерянной записи может соответствовать пропуск номера
ms Миллисекунды от запуска приложения до завершения цикла. Учитываются переполнения аппаратного счётчика
t1, t2 Отдельные объекты каналов. id хранит восемь байт Dallas ROM в порядке передачи, c — число в °C или null, s — состояние
s Что наблюдалось
ok Адрес, цикл преобразования и содержимое памяти результата прошли проверки
no_sensor После сброса шины отсутствует импульс присутствия
bus_short Освобождённая линия DQ удерживается в нуле
wrong_family Обнаружено устройство с другим кодом семейства
multiple_devices В ходе поиска обнаружено расхождение адресных битов
rom_crc Ошибка CRC восьми байтов адреса
parasite_power Датчик сообщил о паразитном питании
conversion_timeout Пропущен ответ «занят» либо истекло время ожидания готовности
scratchpad_crc Ошибка CRC памяти результата
invalid_data Некорректная конфигурация или значение вне диапазона −55…+125 °C
startup_85 Ровно +85 °C совпадает со значением после сброса питания датчика
sensor_changed Изменился достоверный адрес на этом канале. Следующий цикл измерит новый датчик
bus_error Ошибка ввода-вывода или исчезновение ответов во время поиска ROM

Во всех ошибочных состояниях c равно null. Точное значение +85 °C всегда отмечается startup_85 — при перезапуске самого датчика в ходе цикла его стартовый код может иметь правильную CRC. Это ограничение относится и к действительной температуре ровно +85 °C. Разрешение 9–12 бит считывается из конфигурации датчика, неопределённые младшие биты игнорируются.

Воспроизведение сборки

python -m pip install littlefs-python==0.16.0
python build_uf2.py --verify
python build_uf2.py --output LM04B-rebuilt.uf2

Сценарий загружает официальный образ фиксированной версии и проверяет его SHA-256 e0c40eacf1afc550a6add74888c48bb981b28788a6d75a62a0e2444e997b9864. Для локальной копии добавьте --base RPI_PICO-20250415-v1.25.0.uf2. Файловая система LittleFS v2.1 начинается со смещения 0xA0000, содержит 352 блока по 4096 байт и использует размер программирования 256 байт. Сценарий формирует 8192 блока UF2 с идентификатором RP2040, разбирает каждый блок, повторно монтирует файловую систему и сверяет main.py. Команда --verify сравнивает результат с готовым образом побайтово. Конфигурация платы · Размещение флеш-памяти · Монтирование при старте

Проверки

python -m unittest discover -s ../checks -p "test_firmware*.py" -v

21 проверка охватывает код приложения, ошибки двух независимых каналов, замену датчика, переполнения счётчика, пропадание USB, структуру UF2, идентичность базового образа и проверку установки. Для проверки сборки внутри этого набора нужен указанный выше пакет littlefs-python.

Файл qualification-rp2040.jsonl содержит четыре последовательных USB-кадра из готового образа, запущенного на эмуляторе RP2040js 1.4.2. Два программных датчика отвечали на импульсы GPIO, формировали ROM, бит занятости и память результата. Последовательно проверены два показания, отключение T1, замена его ROM и стартовый код +85 °C на T2, затем восстановление двух каналов. Заголовок файла помечает данные как синтетические. Идентификатор виртуальной флеш-памяти и байты генератора случайных чисел здесь определяет эмулятор.

Для повторения нужны Node.js, npm и Python. Команды выполняются из папки прошивки. Последний аргумент задаёт файл с полученными строками.

npm install --no-save --package-lock=false rp2040js@1.4.2
python -c "from urllib.request import urlretrieve; urlretrieve('https://raw.githubusercontent.com/wokwi/rp2040js/v1.4.2/demo/bootrom.ts','bootrom-v1.4.2.ts')"
node qualification/gpio-smoke.cjs LM04B-Pico-v1.uf2 rp2040js bootrom-v1.4.2.ts repeat.jsonl

На хосте сверены байты образа и содержимое файловой системы. Через виртуальный USB CDC версия mpremote 1.25.0 считала файл с работающей MicroPython. Отдельно через тот же интерфейс проверены запись временного файла, проверка его хеша на плате, переименование и побайтовое чтение результата. Для этого теста операции стирания и программирования флеш-памяти Boot ROM выполняла программная модель. Физическая Pico и реальные щупы для проверки отсутствовали.
