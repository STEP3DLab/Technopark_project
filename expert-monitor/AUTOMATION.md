# Регламент очередного цикла мониторинга

## Цель

Найти новые действующие возможности для АНО «МСК-Эксперт» в Москве и ближайшем арбитражном контуре, проверить стадию и обновить публичный реестр и Google Таблицу. Не отправлять обращения, письма и заявки без отдельного указания пользователя.

## Источники и последовательность

1. Прочитать актуальные `data/registry.json`, `data/monitoring.json` и метаданные Google Таблицы из `meta.sheetUrl`. Не восстанавливать старый `research` поверх новых записей.
2. Проверить новые `newCandidates` и ранее найденные будущие сроки. Сначала первоисточник, затем доступные вторичные копии с явной маркировкой.
3. Выполнить поиск по АС Москвы / АС Московской области и московскому порталу судов: «строительно-техническая экспертиза», «направить запрос», «возможность, стоимость и срок», «представить кандидатуры», «повторная экспертиза». Ищем последние определения, а не только итоговые решения.
4. Районные суды просматривать группами по 7 из 35, сохраняя `meta.reviewState.courtCursor`. Полный цикл — пять успешных запусков. Фиксировать каждый источник, который действительно проверен; недоступный не считать просмотренным. Параллельно широкий поиск по всем московским районным судам.
5. Смежные закупки искать отдельно: ЕИС и московские заказчики, предмет — строительная экспертиза, обследование конструкций, дефекты, качество и объёмы работ. Регион объекта и заказчика не путать.
6. Сверять новые записи по стабильному ID: судебные — суд + номер + дата конкретного акта; закупки — реестровый номер + изменение. Не считать один документ отдельным лидом из-за двух агрегаторов.

## Классификация

- Только действующий запрос первоисточника и подтверждённая незавершённая стадия дают `open_confirmed`. Заполнить `openVerifiedAt`, `openEvidenceUrl`; проверить возможное назначение в последующем акте.
- Копия/сниппет без актуальной карточки — `needs_review`. Для таких записей не заявлять гарантию приёма.
- Уже назначенная экспертиза или исполненный договор — `historical` / `closed`, пока новый запрос о замене, дополнительной или повторной экспертизе не подтверждён.
- Если срок по источнику прошёл, исключить запись из актуальных; сохранить прошлое значение и указать, проверено ли продление.
- `amountRub` только из опубликованного материала. Уточнить `amountType` и `amountLabel`; цена иска не превращается в цену экспертизы. `proposalRub` в публичных данных остаётся `null`.
- Для самовольного строительства и иных ограниченных категорий проверить действующую редакцию перечня №3214-р. Не применять изменения со вступлением 01.01.2027 ранее этой даты.
- Не переносить имена и идентификаторы граждан, адреса квартир, личные контакты и рабочие черновики в публичный GitHub.

## Запись результата

Обновлять `meta.asOf` только после фактически выполненной содержательной проверки, а не после успешной загрузки JSON. Сохранить перечень проверенных источников, ограничения и дату. Новый технический `lastRunAt` не доказывает актуальность процессуального статуса.

В GitHub добавлять только файлы внутри `expert-monitor/data/` и проверять актуальный SHA перед записью. Не трогать другие проекты. Для небольшого обновления допустима запись registry.json через Contents API с текущим SHA; не использовать force. GitHub workflow по изменению registry пересоберёт SQLite/CSV. Если workflow недоступен, пересобрать `scripts/database.py` через доступный исполнитель и отдельно сообщить о несинхронных выгрузках.

В Google Таблице прочитать реальные названия вкладок и заголовки. На листе «Дела и закупки» найти строки по ID и менять только исходные поля. **Сохранить колонку «Наша цена, ₽», любые пользовательские заметки, формулы и лист «КП».** Новую запись добавлять строкой; не пересоздавать книгу. Пересчитать сводные формулы и проверить итоговые числа. При расхождении источников отразить его в верификации, не выбирать удобную версию молча.

## Уведомление

Сообщать пользователю только о новом подходящем запросе, изменившемся сроке, возможности со сроком в ближайшие 3 дня или устойчивом блокере, мешающем мониторингу. Приводить суд/заказчика, номер, срок в МСК, сумму с её смыслом, источник и конкретный следующий шаг. Не повторять одно и то же уведомление каждый час; хранить `meta.reviewState.notifiedIds` и дату.

Если значимых изменений нет, не отправлять пустую сводку. Отсутствие результатов не трактовать как отсутствие судебных потребностей.
