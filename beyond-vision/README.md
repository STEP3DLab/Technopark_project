# За пределами зрения

Авторский исследовательский проект в рамках диссертационной работы. Технопарк РГСУ — площадка проведения экспериментальных встреч.

Публичная страница: https://step3dlab.github.io/Technopark_project/beyond-vision/

Сайт публикуется через существующий GitHub Pages репозитория. Интерфейс работает без сборки и внешних библиотек. Все файлы приложения находятся в этом каталоге. `backend/Code.gs` устанавливается владельцем Google-аккаунта как отдельное веб-приложение Apps Script.

## Текущее состояние

Интерфейс опубликован. Создана закрытая Google Таблица с листами для расписания, записей, доступов, ответов и сессий. До развёртывания Apps Script поле `apiUrl` в `config.js` остаётся пустым. В этом состоянии сайт честно показывает, что онлайн-запись и приём ответов ещё не открыты, и не имитирует сохранение данных.

Google Таблица организатора: https://docs.google.com/spreadsheets/d/1C0Bc63nyd-0qp2GniTJ_KxxZAOyBrd3cLBVRLXjnh28/edit

## Запуск Google-сервиса

1. Откройте указанную таблицу от имени её владельца. Выберите **Расширения → Apps Script**.
2. Замените содержимое `Code.gs` кодом из `backend/Code.gs`. ID нужной таблицы уже указан в `APP.spreadsheetId`.
3. В настройках проекта включите отображение файла манифеста. Перенесите содержимое `backend/appsscript.json` в `appsscript.json` проекта.
4. Сохраните проект под названием «За пределами зрения». Выберите функцию `setup` и запустите её. Владелец разрешает работу с таблицами, создание закрытой папки Google Диска для аудио и отправку писем. Папка не публикуется.
5. Выберите **Развернуть → Новое развёртывание → Веб-приложение**. Выполнять от имени владельца; доступ — **Все**. Это открывает только проверяемый кодом серверный интерфейс, а не саму таблицу и аудиопапку.
6. Скопируйте выданный URL, заканчивающийся `/exec`, в `apiUrl` файла `config.js` и сохраните изменение в GitHub. `/dev` не подходит для посетителей.
7. На листе **Окна** добавьте реальное время посещения. Никакие посещения от имени организатора заранее не выдуманы.
8. Пройдите контрольную регистрацию на свою почту. Проверьте письмо, оба способа входа, текст, аудио, продолжение после перерыва и завершение анкеты. Только после этого приглашайте участников.

Ни OAuth-токен, ни секрет Apps Script, ни список кодов не размещаются в GitHub или браузере посетителя. `setup()` создаёт секрет только при первом запуске; повторный запуск не должен менять действующие доступы.

## Одна таблица, разные листы

| Лист | Назначение |
| --- | --- |
| Окна | ID, дата, время, вместимость, статус, адрес и пояснение |
| Записи | ФИО, почта, телефон, просьба о встрече, время, статус письма |
| Ответы | Тексты, оценки, маркировки панелей, ссылки на закрытое аудио |
| Сессии | Незавершённые, завершённые и отозванные анкеты |
| Доступ | Логины, соли и хеши; версии доступа и назначенные панели |
| Настройки | Адрес сайта и открытие записи/опроса |
| Инструкция | Памятка организатору, включая ручной ввод |

Время — `Europe/Moscow`. Для даты используйте `2026-11-23` или `23.11.2026`; для времени — `10:00`. Статус окна — `Открыто` или `Закрыто`. Каждый интервал имеет собственный неизменяемый ID. Не сортируйте строки во время работающей серверной операции.

При регистрации сервер под блокировкой повторно проверяет вместимость. Подтверждённые записи занимают места даже при ошибке письма. Публичное расписание содержит только время, место и число свободных мест. Имена и контакты в календарь не попадают.

Для ручной записи заполните на листе **Записи** ID окна, ФИО, почту, телефон и дату полученного согласия. Выделите строку и выберите **За пределами зрения → Выдать доступ выбранной записи**. Для поступивших списков выполняйте эту команду на каждой подготовленной строке. Письмо и доступ создаёт сервер, а не формулы в таблице.

Пункты меню также позволяют повторить неотправленные письма, отменить посещение и заменить доступ по запросу. Замена отключает прежние код, пароль и токены сеансов. Самостоятельной смены пароля на сайте нет.

## Доступ и письма

Пароль — 18 случайно выглядящих символов из HMAC с серверным секретом и индивидуальной случайной версией доступа; код — 12 цифр. Они воспроизводятся только сервером для письма. В таблице сохраняются соль, хеши и версия доступа. Это решение рассчитано на выдаваемые длинные пароли; не заменяйте их короткими выбранными пользователем паролями без перехода на специальную систему аутентификации.

Проверка доступа и подписей выполняется сервером. Токен сеанса действует 72 часа и хранится только в sessionStorage. Повторный вход с кодом восстанавливает ответы. Ограничение попыток действует через CacheService и не заменяет защиту от крупного сетевого злоупотребления.

Письма отправляются `MailApp` из аккаунта, от имени которого развёрнут скрипт. Сервис не читает входящую почту. Проверяйте дневные квоты аккаунта. Статусы `pending`, `sending`, `sent`, `failed` видны в таблице. Ошибка письма не отменяет запись. Повторное выполнение того же запроса не создаёт вторую запись и не пересылает уже отправленное письмо. Зависшую более пяти минут отправку можно повторить командой меню; после неоднозначного сбоя доставки письмо иногда может прийти повторно.

## Опрос и научная процедура

Каждый участник получает три разные панели и три разных метода. Девять последовательностей повторяются циклом. Для 18 последовательно выданных доступов каждая пара «картина × метод» встречается шесть раз. Отмены и незавершённые анкеты могут нарушить баланс: перед анализом проверяйте фактическую выборку.

Маркировки сохранены совместимыми с исходным протоколом: латинские `S`, `K`, `M`, латинская `A`, кириллические `Б` и `В`. Имена произведений и оценочный ключ в интерфейсе не раскрываются.

Анкета включает согласие, опыт, тренировку, исследование каждой панели, свободный ответ, понятность, уверенность, замечания и итоговое впечатление. Время с телефона — приблизительное и отмечено как `self-reported-phone`, его нельзя смешивать с точным хронометражем ведущего без учёта способа измерения.

Независимость ответов обеспечивается организацией сеанса; сайт напоминает не обсуждать панели до общего обсуждения. Дистанционная анкета сама по себе не подтверждает наличие физических панелей у участника.

Текст или аудио обязательны только для трёх основных описаний; допускается ответ о невозможности распознать изображение. Для шкал есть отказ от оценки; дополнительные текстовые вопросы можно пропустить. Сохраняется последняя редакция ответа, номер редакции и время; полная история текстов не ведётся.

## Аудио и доступность

Запись включается по отдельному согласию и нажатию. `MediaRecorder` выбирает поддерживаемый MIME: WebM/Opus, MP4 или Ogg. Максимум — две минуты и 2,5 МБ. Перед отправкой запись можно прослушать и удалить. Сервер проверяет размер, тип и сигнатуру файла. Аудио не расшифровывается сторонним сервисом; хранится в закрытой папке Drive.

Озвучивание вопросов использует установленный на устройстве голос `speechSynthesis`. Если русская озвучка недоступна, остаются текст и экранный диктор. Микрофон работает только в поддерживаемом браузере по HTTPS с разрешением пользователя. При отказе можно ответить текстом или диктовкой клавиатуры телефона. Нужна дополнительная проверка на реальных iPhone/VoiceOver и Android/TalkBack с целевой группой.

Предусмотрены семантические заголовки, подписи полей, нативные переключатели, управление клавиатурой, заметный фокус, контраст и крупный текст. Автоматическое чтение выключено по умолчанию, чтобы не мешать экранному диктору. Цвет доступности дублируется текстом.

Черновики хранятся локально в IndexedDB и удаляются после подтверждения сохранения соответствующего ответа. Неотправленное содержимое не надо считать полученными данными. Серверное сохранение подтверждается ответом API; `no-cors` и неподтверждённого «успешно» нет. После завершения можно отозвать участие: тексты убираются, аудио перемещается в корзину, анкета исключается из анализа. Сроки дальнейшего хранения и доступ сотрудников определяет организатор.

## Продолжение проекта

- `app.js` — страницы и пошаговый опрос;
- `booking.js` — календарь, запись и файл календаря ICS;
- `questions.js` — вопросы, без оценочного ключа;
- `audio.js` — запись и озвучивание;
- `storage.js` — локальные черновики;
- `api.js` — подтверждаемые сервером операции;
- `assets/` — векторная иллюстрация и памятка проезда;
- `backend/` — сервер Google Apps Script;
- `tests/` — независимые проверки регистрации, доступа и сохранения.

Коллекцию можно добавить отдельным модулем и маршрутом, не изменяя структуру записей или опроса. При изменении состава анкеты меняйте `studyId` одновременно в `config.js` и `APP.studyId`, чтобы новые вопросы не смешивались со старой выборкой.

## Проверки

`npm test` запускает проверки без сетевых обращений и реальных писем: последнее место, повтор запроса, ошибка почты, изоляция ответов, поддельный токен, порядок вопросов, согласия, аудио, отзыв, завершение и баланс 18 назначений. Это проверка кода с имитацией Google API; она не заменяет контрольное прохождение после развёртывания Apps Script.

`npm run build` обновляет статический каталог `dist` для локального предпросмотра. GitHub Pages использует файлы в корне этого каталога проекта, а не `dist`.

Официальные технические описания: [Apps Script Web Apps](https://developers.google.com/apps-script/guides/web), [ContentService](https://developers.google.com/apps-script/guides/content), [MailApp](https://developers.google.com/apps-script/reference/mail/mail-app), [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder).
