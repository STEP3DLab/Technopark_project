# Управление тестами · версия 1.4.1

## Быстрый старт для организатора

После запуска функции setup и обновления страницы Google Таблицы откройте меню **За пределами зрения → Управление тестированиями**. В открывшемся окне три раздела:

- **Конструктор тестов**: новый тест, название, инструкция, вопросы, типы ответов, порядок, копирование вопросов, предварительный просмотр, сохранение черновика, открытие/закрытие и создание новой версии.
- **Участники и коды**: выберите открытый тест, создайте нового участника или назначьте его существующему; при необходимости укажите маркировки физических панелей. Замена действующего назначения требует подтверждения. Код показывается только организатору.
- **Прохождения и ответы**: сводка по выбранному тесту/версии, число назначенных, начатых, завершённых и отозванных; прогресс участников, ссылки на закрытые таблицы ответов и прохождений.

Не нужно вручную придумывать ID, номера вопросов или версии. Использованную версию не редактируют: кнопка «Новая версия» копирует её в новый черновик. Предпросмотр не создаёт ответов.

Весь интерфейс встроен в Code.gs; отдельный HTML-файл в Apps Script создавать не требуется. [Демонстрационный HTML](test-manager-preview.html) не подключается к таблице, не показывает реальные данные и не выдаёт коды.

Проверено 17 сценариев серверной логики редактора на имитации Google Sheets. Работа в реальном диалоге Google и полный приём ответов требуют развёртывания. Исходные таблицы и ручной порядок ниже остаются доступными.

## 1. Однократное подключение

Операционная таблица (не открывать для общего доступа):
https://docs.google.com/spreadsheets/d/1C0Bc63nyd-0qp2GniTJ_KxxZAOyBrd3cLBVRLXjnh28/edit

1. В таблице выберите «Расширения → Apps Script».
2. Вставьте целиком актуальный [backend/Code.gs](backend/Code.gs) вместо старого кода. Если проект уже существует, сначала сохраните старую копию.
3. В настройках проекта включите показ манифеста appsscript.json и перенесите содержимое [backend/appsscript.json](backend/appsscript.json).
4. Сохраните и запустите функцию `setup`. Подтвердите права на таблицы, Drive, отправку писем и меню. Повторный setup не меняет серверный секрет или существующую закрытую аудиопапку.
5. «Развернуть → Новое развёртывание → Веб-приложение» (если уже развёрнуто, обновить версию существующего развёртывания). Выполнять от имени владельца. Доступ — «Все». Таблицу и папку с аудио не публиковать.
6. Передайте URL веб-приложения, заканчивающийся на /exec, для установки в `config.js` (`apiUrl`). Не передавайте токены, секреты и коды участников. /dev не подходит.
7. Выполните контрольное прохождение CHECK до приглашения реальных участников. Пока URL не настроен, сайт не принимает ответы и не имитирует их сохранение.

## 2. Создание теста

На листе «Тесты» добавьте строку: уникальный ID латиницей (например, SAMPLE), версия (1), название для участника, статус «Черновик», инструкция участнику. Комментарий организатора не передаётся на сайт.

На листе «Вопросы» добавьте по строке на вопрос с одинаковыми ID теста и версией. Порядок и ID вопросов должны быть уникальными внутри версии. ID consent и review зарезервированы: согласие и итоговый экран добавляются автоматически. Не помещайте в формулировки вопросы с раскрытием правильного ответа или идентичности физического пробника.

Типы: text (свободный текст или голос при согласии); choice (один вариант); scale (2–10 уровней + отказ от оценки); training (шаг подготовки); explore (таймер ощупывания, нужен номер панели 1–3).
Для choice перечисляйте варианты по одному на строке в формате код|Подпись. Например:
```
a|Первый вариант
b|Второй вариант
skip|Предпочитаю не отвечать
```
Для scale — подписи уровней по одной на строке. Для text — «Да» или «Нет» в колонке обязательности, подпись поля. При обязательном текстовом вопросе допустим голосовой ответ. Для подсказок используются метки {panel1}, {panel2}, {panel3}; они заменяются только маркировками, назначенными участнику.

После проверки переведите тест в «Открыт». Если хотя бы один участник начал версию, её содержание блокируется для новых запусков при попытке изменения: создайте версию 2 с копией всех вопросов, внесите изменения и назначьте новую версию. Начатое прохождение сохраняет неизменный снимок вопросов и панелей. Закрытие теста блокирует новые прохождения, закрытие назначения — доступ к текущему прохождению. Не удаляйте старые записи.

## 3. Выдача кода

**Без регистрации на посещение:** выделите строку открытого теста на листе «Тесты» и выберите меню «За пределами зрения → Создать код для выбранного теста». Укажите маркировки панелей через запятую, если нужны. При пустых маркировках для RELIEF-3 используется исходное автоматическое назначение трёх панелей; для других тестов требуемые маркировки задаются вручную. Для CHECK оставьте поле пустым. Откроется диалог с номером участника и 12-значным кодом. Код передайте лично, не записывайте в общую базу знаний.

**Для записавшегося участника:** найдите его номер Uxxxx на листах «Записи» / «Доступ». На листе «Назначения» добавьте строку: участник, ID теста, версия, «Активно», нужные маркировки панелей. У каждого участника одновременно должно быть только одно активное назначение. Ранее выданный код продолжит действовать для назначенного теста.

Для получения кода снова выделите участника на листе «Доступ» и выберите «Показать код выбранного участника». Коды не хранятся открытым текстом в таблице. Не публикуйте и не пересылайте лист «Доступ».

## 4. Участник

Открывает https://step3dlab.github.io/Technopark_project/beyond-vision/#access, вводит код, видит только назначенную анкету. Согласие обязательно. Вопросы можно слушать, на текстовые отвечать голосом при отдельном согласии. «Далее» подтверждает серверное сохранение; перерыв и повторный вход восстанавливают последний незавершённый шаг. Незавершённые черновики хранятся локально на устройстве. Завершение выдаёт номер подтверждения.

## 5. Следующее тестирование и данные

Для того же человека закройте старое назначение и добавьте новое активное с другим ID теста или версией. Один тест одной версии — одно прохождение на участника. При повторной выдаче той же версии продолжается старое прохождение; для повторного отдельного испытания используйте новую версию/ID. Не меняйте назначение во время прохождения, если это не необходимо. Старый открытый браузер не сможет отправить ответы в новое назначение.

«Прохождения тестов»: один ряд на человека и версию; in_progress — начато, completed — завершено, withdrawn — отозвано. «Ответы тестов»: одна строка на вопрос, с ID прохождения, тестом, версией, порядком, текстом, оценкой, временем, маркировкой и закрытой ссылкой на аудио. Повтор того же запроса не создаёт дубль; изменение ответа до завершения увеличивает редакцию. Ответы CHECK не включать в исследовательскую выборку. Старые листы «Сессии» и «Ответы» сохранены для истории. Ответы и ключи эксперимента не переносить в публичный репозиторий или общую базу знаний.

## 6. Контрольный запуск

Создать код CHECK → войти с телефона → принять согласие → выбрать вариант → написать текст (и отдельно проверить запись аудио при согласии) → выйти → войти повторно → завершить → убедиться, что в «Прохождения тестов» появился completed, в «Ответы тестов» — все четыре шага с правильным ID → назначить другой технический тест/версию и проверить раздельность → при необходимости отозвать пробные ответы.

Проверки логики выполнены в имитации Google Sheets (назначение, разделение участников и тестов, недопустимые значения, порядок, повтор запроса, обязательность, согласие, восстановление, завершение, отзыв, блокировка изменения версии). Развёртывание, Google OAuth, реальные записи/аудио и браузерная проверка с подключённым сервером требуют контрольного запуска. Не считать систему запущенной до получения рабочего /exec.
