# Рабочий кабинет пилота полных сообщений

11 ноября 2026. [Открыть кабинет](../app/pilot.html).

Кабинет помогает собрать и проверить материал для сценария «Встреча посетителя». Он использует те же 20 смысловых сообщений, которые зафиксированы в [задании на запись](PILOT_RECORDING_BRIEF.md). Новых записей РЖЯ и оценок участников в комплект не добавлено. Перевод полных сообщений и распознавание свободной речи этим интерфейсом не реализуются.

## Что можно сделать

1. Выбрать смысловую карточку и зарегистрировать локальную видеозапись носителя РЖЯ или движения аватара. В реестр попадают условный код исполнителя, раздел данных, номер дубля, длительность, размеры кадра и SHA-256. Русская фраза задаёт смысл, а не последовательность жестов.
2. Указать состояние языковой проверки. Начальный статус — «Ещё не проверено». После регистрации материала можно добавить проверку и замечания через его карточку. История проверок сохраняется отдельно от исходной записи, актуальным считается последний внесённый статус. Для отметки о выполненной проверке требуется код проверяющего. Это запись исследователя о проверке, а не автоматически подтверждённый результат.
3. Зафиксировать задание до попытки. Для проверки распознавания указывают код исполнителя исходного видео; для проверки понятности — код нового зрителя. Один код не может попадать в train, validation и test одновременно. Видеоматериал должен соответствовать ожидаемому сообщению.
4. Показать локальное видео на отдельном экране без русской подписи. Участник записывает пересказ или выбирает отказ / пропуск. Ответ сохраняется до оценки и далее не редактируется.
5. Добавить отдельную оценку смысла, отрицания / утверждения и вопроса / сообщения. Уточнённый текст хранится отдельно от исходного ответа. Оценки нескольких проверяющих сохраняются отдельными строками; оценка одного проверяющего не перезаписывается.
6. Скачать весь проект в JSON, таблицу исходных попыток и оценок в CSV и реестр материалов в CSV. JSON можно открыть для продолжения. CSV экранирует потенциальные формулы табличных редакторов.

## Где находятся данные

По умолчанию проект существует только в открытой вкладке. Сохранение в браузере включается отдельным флажком. При следующем открытии страницы пользователь сам выбирает восстановление сохранённой копии. Перед переносом на другой компьютер нужно скачать JSON.

Видеофайлы остаются на устройстве и не входят в JSON или хранилище браузера. После переноса проекта их подключают заново; кабинет сверяет SHA-256. Исходное имя файла не сохраняется в реестре, чтобы не переносить в отчёт случайные персональные сведения из названия. Перед добавлением материала исследователь подтверждает согласованное использование записи; сами согласия хранятся у организатора отдельно.

Нужны HTTPS или локальный HTTP-сервер, JavaScript и поддерживаемый браузером видеоформат. Для просмотра используются обычные средства браузера. Новая камера, облачная обработка и распознавание этой страницей не запускаются.

## Правила исследования

- Для обучения / образцов, настройки и итоговой проверки используйте разные коды людей. Все дубли одного человека остаются в одном разделе. Один браузер не может выявить, что одному человеку присвоили разные коды, поэтому организатор ведёт единый реестр.
- Исполнитель аватара обозначается кодом человека, по записи которого подготовлено движение. Зритель в проверке понятности должен быть другим человеком.
- В распознавании видео исполнителя из train нельзя обозначить как новое test-видео, просто введя другой код участника.
- Сохраняйте ошибки, отказы, пропуски и повторные попытки. Повторение получает следующий номер; первая попытка не заменяется лучшей.
- Отдельно оценивайте понятность человеку и распознавание системой, источники видео и аватара, разные разделы, первые и повторные попытки. Общая метрика «точность» для смешанного журнала не выводится.
- Ручная оценка и пометка «отдельный проверяющий» фиксируют сведения исследователя; кабинет не проверяет квалификацию специалиста и независимость организационно.
- Экспортированный JSON валидируется по схеме и правилам исследования, но не подписан криптографически. Это рабочий журнал, а не средство удостоверения неизменности внешнего файла.

## Структура реализации

`app/pilot-model.js` содержит чистые функции реестра и проверки инвариантов. `app/pilot.js` связывает их с локальным интерфейсом. `app/assets/pilot-messages.json` хранит неизменный протокол 20 сообщений. `app/pilot.html` и `app/pilot.css` дают отдельную страницу, не изменяя распознаватель и демонстратор шести слов.

Схема экспорта: `schemaVersion: 1`, `protocolVersion: visitor-v1`; разделы `participants`, `materials`, `languageReviews`, `attempts`, `reviews`. Каждая попытка содержит ожидаемый ID и исходный ответ. Оценки ссылаются на попытку через `attemptId`; языковые проверки — на материал через `materialId`.

Проверки модели: точное совпадение 20 сообщений с прежним заданием; отсутствие вымышленных результатов; запрет пересечения разделов по исполнителю; контроль повторов видео и попыток; сохранение отказов и пропусков; неизменность исходного ответа при оценке; раздельные оценки проверяющих; импорт без подмены цели; безопасный CSV. Это проверки программных правил, а не испытание качества РЖЯ.
