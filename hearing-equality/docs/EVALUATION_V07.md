Верный ответ требует одновременно правильной метки и прохождения порогов принятия. Если ближайший образец верный, но уверенного отрыва от второго нет, результат остаётся отказом. В качестве диагностики top-1 без порогов: 6/12 для v0.6 и 7/12 для v0.7. Эти числа не заменяют результат с отказами.

## Что было зафиксировано до вычисления ответов

1. Шесть слов текущего каталога. Два клипа на слово из `train=False` официальных аннотаций Slovo: первые по UUID, разные исполнители внутри слова, исключены исполнители исходных шаблонов и кандидатов для отображения. Получилось 12 разных исполнителей. Плохой трекинг не исключался после отбора.
2. Три исполнителя обучающего раздела: исходный и два других. Для каждого слова взят первый по UUID клип каждого исполнителя (18 записей). К ним добавлены шесть текущих записей отображения; после удаления повторяющихся UUID — 21. Исполнителей контрольной группы здесь нет.
3. Кандидаты для отображения выбирались по полноте измеренных кистей, не по результату классификации. Три записи заменены.
4. Алгоритм `recognizer.js` не изменён: nearest-template DTW; минимальное расстояние по каждому слову; принятие при расстоянии < 0.42 и отрыве от следующего слова > 0.055. Пороги и состав шаблонов после просмотра этой проверки не подбирались.

## Обработка и воспроизведение

Исходные видео извлечены из официального архива Slovo HTTP-диапазонами, без скачивания всего архива. SHA-256, UUID и путь внутри ZIP сохранены с каждым набором признаков. Python MediaPipe Holistic 0.10.21 извлёк координаты с одинаковыми настройками. `makeSequence` использует нормализацию плеч и ладоней, явные пропуски; затем остаётся до 40 кадров с округлением координат до шести знаков. Оба варианта сравниваются на одних и тех же компактных признаках. Межкадровая интерполяция аватара в распознавании не используется.

```sh
npm test
npm run verify
npm run evaluate
```

`node scripts/evaluate.mjs --write` обновляет сохранённый JSON; тест сверяет его с пересчитанным результатом. Для повторного извлечения: `python scripts/fetch_slovo_subset.py /path/to/videos`, затем `python scripts/extract_motion.py /path/to/videos/*.mp4 --output /path/to/motion` в окружении с MediaPipe 0.10.21. `node scripts/rebuild_features.mjs /path/to/motion` сверяет признаки; `--write` перезаписывает их. Повторная детекция другой версией/платформой может отличаться; сохранённые признаки позволяют точно воспроизвести именно классификацию этого эксперимента.

## Ограничения и следующий тест

Всего две записи на слово — недостаточно для устойчивых оценок. В наборе только известные слова, нет неизвестных жестов и свободной речи, нет повторений каждого участника в разных условиях. Ноль ошибочных принятых ответов на 12 записях не доказывает отсутствие таких ошибок. Это внутренний эксперимент на публичном датасете, не независимая внешняя экспертиза. Python-извлечение и браузерная модель — разные цепочки; перенос результата на живую камеру не проверен. Лингвистическая корректность исходных меток принята из датасета, не оценена заново.

Следующий этап: отдельная группа носителей РЖЯ, физические телефоны, фиксированные задания и условия, неизвестные слова, персональные образцы отдельной серией. Текущие 12 записей уже просмотрены и не должны использоваться как новая независимая итоговая проверка после дальнейшей настройки.

В приложении добавлена серия из 12 заданий: каждое слово дважды в случайном порядке. Фиксируются задание, условный код, исходный ответ до исправлений, пропуски, отказы, наличие персональных образцов и время. Есть две секунды подготовки и три секунды записи. Эта серия — инструмент для будущего испытания, а не проведённое испытание на телефонах.
